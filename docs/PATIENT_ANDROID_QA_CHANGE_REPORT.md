## Exact backend findings (read-only)

See the bilingual [lead cooldown review](LEAD_COOLDOWN_REVIEW_FOR_ALI.md) for Django paths, predicates and proposed code:

- Consultation duplicate window is **30 seconds**: account + clinic + patient name + treatment UUID/service text. Practitioner and branch do not distinguish requests.
- Manual duplicate rejection is **429**, raw `detail`, no code or Retry-After; it returns before a new lead save. A cache lock/cache failure is not proof an earlier lead exists.
- Lead creation checks **10/hour** but inherits DRF's `user` cache scope. Default-throttled authenticated reads/writes share `throttle_user_<user-pk>` history at their configured 2000/hour rate. Unrelated browsing can therefore consume the effective allowance. Proposed separate lead scope preserves the numerical protections and needs backend review, not a frontend bypass.
- Successful rows appear at account-scoped `GET /api/v1/leads/my/`. List and detail ownership is enforced by `request.user`; no arbitrary patient selector is added.

See the bilingual [rating/media handoff](PATIENT_ANDROID_QA_HANDOFF_FOR_ALI.md) for evidence and safe anonymous PowerShell capture:

- Source retains rating/count when a Place ID is removed or a no-ID sync is skipped. A configured but wrong/old ID still needs backend ownership/provenance correction.
- Home has a 300-second `aw:home:feed:*` cache; clinic mutation signals delete different snapshot keys. Flutter coalesces in-flight GETs without persistent JSON caching; mounted models and unmatched cached feed entries can still be stale.
- The Brautyplus live record, deployed revision, CDN/cache state and media HTTP/decode success are unverified. Runtime network policy excludes aestheticway.ae. No fixture screenshot proves production correctness.
- Reported anime, personal product portrait, gallery screenshot and placeholder-like copy need owner/admin review of actual record/asset IDs. No live content was deleted, fabricated, relabeled as genuine media or replaced with reference photos.

## Navigation and design review

Use **Profile → My Requests**, **successful consultation → View My Requests**, or **rejection notice → View My Requests**. Tap a history card to see source-backed clinic, service, practitioner, date and reference. Back from history returns to the previous route; from the rejection route it retains the form. No appointment or reservation is confirmed. Bottom navigation remains Home, Clinics, Products, Offers, Profile; the exact Arabic success text remains `تم إرسال طلبك وستتواصل العيادة معك`.

[20 before / 24 after Flutter renders, 20 comparison boards and capture hashes](patient-android-qa/README.md) show the targeted changes. Missing-media cards are visibly smaller; real photo areas stay prominent. Light/dark, English/Arabic RTL, 160% history text and form state retention are covered. Prior eight-reference design work, Featured carousel, internal placement entitlements, Admin/Clinic workflows, security and performance history are preserved. This review does not replace the approved design mapping or start a separate redesign/security/scalability task.
