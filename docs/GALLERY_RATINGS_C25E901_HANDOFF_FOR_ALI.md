## Conditional gallery list defect — multiple memberships

Reproduce: one admin has active memberships in clinicsA/B. Upload one gallery
asset to each using its explicit `clinic_id`; both return201. Then:

```http
GET /api/v1/media/?media_type=clinic_gallery&clinic_id=<A UUID>&page=1&page_size=20
```

Actual200 includes **both assigned clinics**, because `MediaAssetListView`
honors `clinic_id` only for Super Admin. Flutter correctly rejects an ambiguous
current-editor collection instead of hiding rows/corrupting pagination.
Required: documented current-tenant filtering for clinic users, validating the
requested/JWT clinic against active membership and active/pending/nondeleted
state. Foreign memberships must not grant access; preserve stable counts/pages.
This conditional source defect is **not** the owner's confirmed pre-Save cause.

**عربي:** مشرف بعضويتين يتلقى صور العيادتين حتى عند طلبA وحدها. يرفض Flutter
هذه النتيجة لحماية سياق المحرر. يلزم ترشيح موثق للعيادة الحالية مع التحقق من
العضوية والصلاحيات ودقة الصفحات. ليس هذا سبب اختفاء الاختيار قبل الحفظ.

## P0 — Google place existence is not clinic identity approval

Source details uses Google FieldMask
`id,displayName,formattedAddress,location,googleMapsUri,addressComponents` and
verifies UAE coverage. A clinic admin obtains its legitimate one-use proof:

```http
POST /api/v1/clinic-portal/profile/google-business/details/
{"place_id":"<selected real place>"}

POST /api/v1/clinic-portal/profile/google-business/link/
{"place_id":"<same place>","selection_proof":"<one-use server proof>",
 "expected_current_place_id":"<previous value>"}
```

The controlled probe uses an **unrelated salon** for a disposable medical
clinic: link200, `google_link_status=linked_verified_place`, ratingnull/count0,
statuspending. After a stubbed Google sync (4.6/42), public GET
`/api/v1/clinics/<clinic UUID>/` exposes **4.6/42 for the wrong business**. The
public API contains no identity-review verdict/name/provenance to distinguish it.
The number is a test-provider value, not a real salon rating.

Required: unlink the known unrelated production test association; do not sync it
to make a badge appear. Enforce the clinic's actual business affiliation and
medical eligibility through an approved server review/verification policy.
Persist source identity/provenance; suppress public rating until that policy
authorizes this clinic/place pairing. Place existence, admin confirmation and
rating sync must not be described as Google Business Profile ownership proof.
Supply read-only public verdict/provenance if Flutter is expected to gate it.
No guessed name matching, invented fields or bypass was added to Flutter.

**عربي:** يقبل المصدر ربط عيادة تجريبية بصالون غير تابع لها ثم ينشر تقييم الصالون
للعيادة بعد المزامنة. الإثبات يثبت مكان Google المختار لا تبعيته للعيادة. يجب

`clinics.sync_google_places` runs daily03:00 Asia/Dubai and excludes account status
pending/nonactive/deleted. Pending accounts can therefore remain pending despite
running Celery. In controlled active fixtures, sync persists values and fresh
public/private GET returns them; a provider403 before first sync produces
failed/null/0. Existing Flutter parses `"4.60"`/42 and renders it correctly.

For the affected legitimate clinic, inspect privately: account status vs setup
approval, exact selected identity, `google_sync_status`, nullable rating/count,
last successful timestamp, sanitized sync error class, Beat last dispatch/task
registration, queue routing/worker receipt, lock key TTL, setting enabled, and
Google key/API/billing/quota/outbound readiness. Compare fresh private profile,
public detail and list/Home response values. A functioning Maps deep link uses
neither the server rating key nor the background worker and proves neither.

Expected product decision: eligible, correctly approved associations should have
a documented bounded first-sync path; pending clinics should have explicit sync
eligibility/status semantics. Do not relax publication or deletion security.
No live null/non-null response or provider failure was available here; do not
infer production health from our source tests or from a running worker process.

## P1 — rating fetch can restore a superseded association

Reproduce: `sync_clinic` loads old placeA; while its provider fetch is in flight,
the database receives a valid newer associationB. Complete the old rating fetch.
`Clinic.save` sees oldA on the stale instance, adds `google_place_id` to
`update_fields`, writesA back and resets rating/sync to null/pending. The probe
confirms the newer association is lost. The task can return success despite this.

Required: compare-and-set/version or a short transaction when applying fetched
values, conditioned on current association still matchingA. Do not hold a DB
lock during a provider request. Discard stale results; never rewrite a newer
Place ID/Maps identity from a rating worker. Test relink and unlink during sync.

**عربي:** قد تعيد مهمة قديمة Place ID السابق فوق ربط أحدث أثناء جلب التقييم.
يلزم تحديث مشروط بالهوية/الإصدار الحالي بعد الجلب وإهمال النتيجة القديمة، دون
