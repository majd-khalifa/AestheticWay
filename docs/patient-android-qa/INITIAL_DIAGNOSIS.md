Django separates consultation duplicates (30 seconds; account + clinic + patient name + treatment UUID or service text) from the explicit authenticated lead-creation throttle (10/hour). Follow-up verification of pinned DRF confirms the latter inherits `user` scope and shares history with unrelated authenticated default-throttled calls; see the exact cache-key collision in the cooldown handoff. Practitioner, branch, notes and phone do not distinguish duplicates. Manual duplicate 429 returns raw `detail`, no error code and no Retry-After; the global throttle uses `error.code=RATE_LIMIT_EXCEEDED`, `error.retry_after` and standard DRF Retry-After behavior. A duplicate/cache-lock rejection returns before saving; cache failure is fail-closed, so it does not prove an earlier lead exists.

Cache investigation: Home writes `aw:home:feed:*` keys for 300 seconds. Clinic signals invalidate snapshot/detail keys including `snap:home_feed`, which do not match those Home keys. Directory/detail view source has no response cache. Flutter coalesces in-flight GET requests but has no completed HTTP response cache; mounted screens retain models until reload. Home replaces feed clinics by UUID only when present in its first bounded directory page. These facts identify possible stale-data paths, not the current live cause.
